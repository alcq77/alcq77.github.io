LibreOffice 实现 DOC、XLS、PPT 在线预览

知知行笔记·约 38 分钟阅读
libreofficejodconverterdocxlspptpdfjavapreview文档转换在线预览UNO进程管理

系统已经能预览 PDF，旧版 DOC、XLS、PPT 却打不开时，可以在服务端用 LibreOffice 把它们转成 PDF，继续用原来的阅读器展示。点击文件后仍然打开预览弹窗，转换和等待放在弹窗内部处理。

1. 三种格式怎么转

原格式 转换组件 输出 显示效果
.doc Writer PDF 缺字体、复杂分页和嵌入对象可能影响版式
.xls Calc PDF 按打印布局分页，不是可编辑、可筛选的电子表格
.ppt Impress PDF 展示静态幻灯片，不保留动画、视频和交互

处理顺序：浏览器申请预览 → 后端检查文件权限和版本 → 下载到临时目录 → LibreOffice 转 PDF → 保存预览文件 → 浏览器读取 PDF。

原文件保留，生成的 PDF 单独存放。XLS 转出的 PDF 按打印布局分页，适合看报表；如果要冻结表头、筛选或查看大量数据，用表格阅读器更合适。

LibreOffice 安装在实际执行转换的机器上。Java 服务运行在容器中时，宿主机安装 Office 并不代表容器能使用；应放进转换容器镜像，或调用独立的转换服务。纯静态网站则在构建机器上提前转换，发布生成结果，浏览器里不运行 LibreOffice。

2. 安装 LibreOffice 和字体

运行转换的普通用户需要读取输入文件，并能写入工作目录和用户配置目录。安装软件需要相应 sudo 授权，不需要让转换服务长期以 root 运行。

Ubuntu / Debian：安装 LibreOffice、字体和检查工具 
sudo apt-get update # 更新已配置的软件源索引
sudo apt-get install -y libreoffice-writer libreoffice-calc libreoffice-impress fonts-noto-cjk fonts-liberation poppler-utils fontconfig # 安装三类转换组件、字体及PDF检查工具
fc-match sans:lang=zh-cn # 查看中文默认匹配到的字体

返回 Noto CJK 等中文字体后，再转一份带中文的文件。打开 PDF 看一下标题、表格和分页是否正常。

使用 dnf 的 RHEL 系：安装转换组件 
sudo dnf install -y libreoffice-writer libreoffice-calc libreoffice-impress fontconfig poppler-utils # 从当前发行版的软件源安装转换组件
sudo dnf search 'cjk' # 查询本发行版提供的中文字体包，按结果选择安装

安装后执行 fc-match sans:lang=zh-cn 检查字体匹配，并打开转换后的 PDF 查看实际显示。

先查版本和程序位置：

command -v soffice # 检查是否可以通过PATH找到转换程序
command -v libreoffice # 某些发行版通过这个启动脚本提供入口
soffice --version # 记录实际Office版本；若只有libreoffice命令，改用它

Java 中的 officeHome 是安装根目录，不是 soffice 文件路径。例如根目录可以是 /usr/lib/libreoffice 或 /usr/lib64/libreoffice，必须以实际安装为准：

ls -l /usr/lib/libreoffice/program/soffice /usr/lib64/libreoffice/program/soffice 2>/dev/null # 检查常见安装位置，缺失项不显示

例如存在 /usr/lib64/libreoffice/program/soffice，对应的 officeHome 才是 /usr/lib64/libreoffice。找不到时，通过包清单查询，不凭发行版名称硬编码：Debian 系使用 dpkg -L libreoffice-core，RPM 系使用 rpm -ql libreoffice-core。

3. 用命令行验证转换

先在转换机器上跑一次命令，确认 Office 本身能工作。准备一份能正常打开的 sample.doc，修改下面的程序和文件路径。timeout 用于限制这次转换的等待时间。

SOFFICE=/usr/lib/libreoffice/program/soffice # 改成已确认的Office启动程序
SOURCE=/srv/preview-input/sample.doc # 改成一份真实、非空的测试文件
PREVIEW_WORK=$(mktemp -d /tmp/office-preview.XXXXXXXX) # 创建本次独立工作目录，失败时停止
printf '%s\n' "$PREVIEW_WORK" # 记录本次目录，后续检查与清理只操作它
test -x "$SOFFICE" && test -s "$SOURCE" # 确认可执行程序和非空源文件；失败时不要继续
mkdir "$PREVIEW_WORK/output" # 创建本次输出目录

以下步骤使用上面同一终端中的变量：

timeout --kill-after=10s 120s "$SOFFICE" "-env:UserInstallation=file://$PREVIEW_WORK/profile" --headless --norestore --convert-to pdf --outdir "$PREVIEW_WORK/output" "$SOURCE" # 使用独立用户配置目录，无界面转换为PDF
CONVERT_EXIT=$? # 紧接上一条记录退出码，后续命令会覆盖$?
printf 'exit=%s\n' "$CONVERT_EXIT" # 0表示命令正常结束；124通常表示timeout达到限制
find "$PREVIEW_WORK/output" -maxdepth 1 -type f -name '*.pdf' -ls # 检查本次是否真正生成了PDF

以 sample.doc 为例，输出应为 output/sample.pdf。替换为 sample.xls 或 sample.ppt 后，可分别验证 Calc 和 Impress。不要把其他格式直接改后缀充当旧格式样本。

三种文件分别看一遍结果。DOC 看字体、表格和分页，PPT 看每张幻灯片的文字有没有溢出。XLS 打开正常但 PDF 只显示一半时，先在 Calc 的打印预览里看打印区域、纸张方向和缩放。横向列太多时，可先试按一页宽缩放，高度仍允许分页，避免整张表被缩得读不清。修改打印设置时用副本，保留原件。

test -s "$PREVIEW_WORK/output/sample.pdf" # 检查文件存在且非空
head -c 5 "$PREVIEW_WORK/output/sample.pdf" # 正常PDF通常以%PDF-开头；这不是完整的有效性校验
pdfinfo "$PREVIEW_WORK/output/sample.pdf" # 检查PDF能否解析，以及页数、尺寸和是否加密

示意输出：退出码为 0，文件存在，pdfinfo 显示合理页数。仍要在阅读器中检查中文、表格、分页和幻灯片内容。只看到退出码为 0 或 %PDF-，不能证明转换内容完整。

--headless 表示无界面运行，不是安全沙箱，也不能当成禁止宏的开关。以上命令用于受信任文件的环境验证；上传文件的转换还需要后文的访问控制、宏策略和运行隔离。参数含义见 LibreOffice 命令行说明。

检查完以后只清理本次临时目录：

case "$PREVIEW_WORK" in /tmp/office-preview.????????) rm -rf -- "$PREVIEW_WORK" ;; *) printf '目录不符合本次临时目录规则，停止清理\n' ;; esac # 校验目录前缀和随机段后删除，绝不删除输入目录

4. Java 转换示例

示例使用 JDK 17、Maven 和 JODConverter 4.4.10。JODConverter 管理 Office 进程和转换调用，服务器上仍要安装 LibreOffice。换用 5.x 时，需要一并调整对应 API。

4.1 Maven 配置

新建独立示例目录，保存以下完整 pom.xml：

<project xmlns="http://maven.apache.org/POM/4.0.0"
         xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
         xsi:schemaLocation="http://maven.apache.org/POM/4.0.0 https://maven.apache.org/xsd/maven-4.0.0.xsd">
  <modelVersion>4.0.0</modelVersion>
  <groupId>example.preview</groupId>
  <artifactId>office-preview-demo</artifactId>
  <version>1.0.0</version>
  <properties>
    <maven.compiler.release>17</maven.compiler.release>
    <project.build.sourceEncoding>UTF-8</project.build.sourceEncoding>
  </properties>
  <dependencies>
    <dependency>
      <groupId>org.jodconverter</groupId>
      <artifactId>jodconverter-local-lo</artifactId>
      <version>4.4.10</version>
    </dependency>
  </dependencies>
  <build>
    <plugins>
      <plugin>
        <groupId>org.apache.maven.plugins</groupId>
        <artifactId>maven-compiler-plugin</artifactId>
        <version>3.13.0</version>
      </plugin>
    </plugins>
  </build>
</project>

jodconverter-local-lo 使用 LibreOffice 的 UNO 库；不要为了补依赖，再叠加一套不同版本的 UNO 库。依赖选择见 JODConverter 4.4.10 Java 接入说明。

4.2 程序怎样接管 LibreOffice

Java 不是直接解析 DOC、XLS、PPT。实际工作分成三层：

  • LocalOfficeManager：启动本机的 soffice，管理用户配置目录、UNO连接和进程回收。
  • LocalConverter：通过管理器提交“打开文件 → 导出PDF”的转换调用。
  • LibreOffice进程：使用Writer、Calc或Impress读取文件，完成排版和导出。

调用 manager.start() 时，管理器根据 officeHome 找到启动程序，为自己管理的进程准备用户配置目录，并建立 UNO 连接。示例配置了 startFailFast(true)，启动失败会在这里报错，不能把一个未启动成功的管理器交给后续任务。

UNO是程序与Office之间的通信接口。127.0.0.1:2002 是示例中的本机连接地址，不是HTTP预览地址。浏览器仍访问文件服务的HTTP接口，不连接2002；也不用在Nginx中转发这个端口。

程序中的位置 做什么
创建转换器 保存安装路径，创建自己的工作目录，暂不启动Office
第一次调用convert 创建并启动管理器，成功后保存实例
后续调用convert 复用同一个管理器和Office进程
达到进程任务数或触发管理器恢复机制 由管理器按配置回收或重启进程
应用关闭 停止接收新任务，调用close，停止管理器并清理工作目录

ExistingProcessAction 怎么选

existingProcessAction 决定管理器启动时，发现已有 Office 进程使用同一个 UNO 连接串（例如 127.0.0.1:2002）该怎么处理。

取值 对已有进程的处理 什么时候用
FAIL 抛出启动异常，保留已有进程 本例使用这个值。发现冲突后先查进程归属，再决定是否换端口
KILL 结束已有进程，再启动新进程 端口由本服务独占，而且允许替换旧进程时使用。4.4.10 默认是这个值
CONNECT 尝试连接已有进程，连接失败则报错 已确认已有 Office 进程可供本服务复用时使用
CONNECT_OR_KILL 先尝试连接已有进程，连不上就结束它，再启动新进程 允许复用并且允许替换该进程时使用

例如，上一个实例还占着 2002，本例用 FAIL 会报错并保留原进程。先用第 9 节的 ss 命令看监听者。如果端口由另一个服务使用，就为当前实例另选空闲端口。若监听者是其他程序，按端口冲突排查。

连接已有 Office 后，还要看 keepAliveOnShutdown。4.4.10 默认值是 false，管理器关闭时会尝试停止 Office。设为 true 时，管理器关闭只断开连接，Office 进程继续运行。遇到同一连接串的处理方式和关闭时是否保留进程，由这两个参数分别控制。JODConverter 4.4.10 本机进程配置

部署时只需在转换机器上安装LibreOffice，不用另外启动一个Office服务。首次转换前看不到soffice进程是正常的；Java程序提交任务后才会启动它。

下面用两个文件演示接管过程。把 officeHome 换成第 2 节查到的安装根目录，first 和 second 传入可读取的旧版 Office 文件，方法返回两个 PDF 所在的目录。依赖沿用 4.1 节。

import com.sun.star.document.MacroExecMode;
import org.jodconverter.core.office.OfficeUtils;
import org.jodconverter.local.LocalConverter;
import org.jodconverter.local.office.ExistingProcessAction;
import org.jodconverter.local.office.LocalOfficeManager;

import java.nio.file.Files;
import java.nio.file.Path;

public final class OfficeProcessDemo {
    public static Path convertPair(String officeHome, Path first, Path second) throws Exception {
        Path work = Files.createTempDirectory("office-process-demo-");
        LocalOfficeManager manager = LocalOfficeManager.builder()
                .officeHome(officeHome)                         // 安装根目录，其下有 program/soffice
                .workingDir(work.toFile())                      // 管理器在这里准备进程的用户配置
                .hostName("127.0.0.1").portNumbers(2002)        // Java 通过本机 UNO 连接 Office
                .existingProcessAction(ExistingProcessAction.FAIL) // 遇到已有 Office 进程时启动失败
                .startFailFast(true)                           // 等待 Office 启动并建立连接
                .taskExecutionTimeout(120_000L)                // 单个转换任务最多执行 120 秒
                .build();

        try {
            manager.start();                                   // 启动 soffice，无需手工启动
            LocalConverter converter = LocalConverter.builder()
                    .officeManager(manager)
                    .loadProperty("MacroExecutionMode", MacroExecMode.NEVER_EXECUTE)
                    .build();
            converter.convert(first.toFile()).to(work.resolve("first.pdf").toFile()).execute();
            converter.convert(second.toFile()).to(work.resolve("second.pdf").toFile()).execute();
            return work;                                       // 两次转换共用一个管理器
        } finally {
            OfficeUtils.stopQuietly(manager);                   // 转换失败时也尝试关闭 Office
        }
    }
}

例如传入 sample.doc 和 slides.ppt，转换后查看返回目录里的 first.pdf 和 second.pdf，检查完再清理本次目录。要验证 XLS，把任意一个输入换成真实的 .xls。如果启动报端口冲突，先用第 9 节的 ss 命令确认谁在监听，再为该实例分配空闲端口。

长期运行的服务可用下一节的 OfficeToPdf。服务只创建一次，后台任务调用同一个实例的 convert，停止接收任务后再调用 close。convert 和 close 共用一把锁，转换和关闭按顺序执行。

4.3 可复用的转换器

保存到 src/main/java/example/preview/OfficeToPdf.java。此程序只负责转换已获准读取的本地文件，不包含上传接口、鉴权和异步队列。

package example.preview;

import com.sun.star.document.MacroExecMode;
import org.jodconverter.core.office.OfficeUtils;
import org.jodconverter.local.LocalConverter;
import org.jodconverter.local.office.ExistingProcessAction;
import org.jodconverter.local.office.LocalOfficeManager;

import java.io.InputStream;
import java.nio.charset.StandardCharsets;
import java.nio.file.Files;
import java.nio.file.Path;
import java.util.Comparator;
import java.util.Locale;
import java.util.Set;
import java.util.stream.Stream;

/** 管理本机Office进程，将已获准读取的文件转成PDF。 */
public final class OfficeToPdf implements AutoCloseable {
    private final String officeHome;
    private final Path work;
    private LocalOfficeManager manager;
    private boolean closed;

    public OfficeToPdf(String officeHome) throws Exception {
        this.officeHome = Path.of(officeHome).toAbsolutePath().normalize().toString();
        this.work = Files.createTempDirectory("office-preview-");
    }

    public synchronized void convert(Path source, Path destination) throws Exception {
        if (closed) throw new IllegalStateException("转换器已关闭");
        Path input = source.toAbsolutePath().normalize();
        Path output = destination.toAbsolutePath().normalize();
        String name = input.getFileName().toString().toLowerCase(Locale.ROOT);
        int dot = name.lastIndexOf('.');
        String extension = dot < 0 ? "" : name.substring(dot + 1);
        if (!Set.of("doc", "xls", "ppt").contains(extension)) {
            throw new IllegalArgumentException("只接受doc、xls、ppt");
        }
        if (!Files.isRegularFile(input) || Files.size(input) == 0
                || Files.size(input) > 50L * 1024 * 1024) {
            throw new IllegalArgumentException("源文件必须存在、非空，且不超过50MB");
        }
        if (!output.getFileName().toString().toLowerCase(Locale.ROOT).endsWith(".pdf")
                || Files.exists(output)) {
            throw new IllegalArgumentException("输出必须是尚不存在的PDF文件");
        }
        Files.createDirectories(output.getParent());
        Path job = Files.createTempDirectory(work, "job-");
        try {
            startIfNeeded();
            Path pdf = job.resolve("preview.pdf");
            LocalConverter.builder().officeManager(manager)
                    .loadProperty("MacroExecutionMode", MacroExecMode.NEVER_EXECUTE)
                    .build().convert(input.toFile()).to(pdf.toFile()).execute();
            if (!Files.isRegularFile(pdf) || Files.size(pdf) < 5) {
                throw new IllegalStateException("未生成有效的PDF文件");
            }
            try (InputStream stream = Files.newInputStream(pdf)) {
                String header = new String(stream.readNBytes(5), StandardCharsets.US_ASCII);
                if (!"%PDF-".equals(header)) throw new IllegalStateException("输出不是PDF");
            }
            Files.copy(pdf, output); // 不覆盖原文件或已存在的PDF
        } finally {
            deleteTree(job); // 每次任务完成后清理本次PDF和转换暂存文件
        }
    }

    private void startIfNeeded() throws Exception {
        if (manager != null) return; // 已启动，复用现有管理器
        LocalOfficeManager candidate = LocalOfficeManager.builder()
                .officeHome(officeHome)
                .workingDir(work.toFile())
                .hostName("127.0.0.1") // UNO只监听本机
                .portNumbers(2002) // 同一台机器上不同管理器应分配不同端口
                .existingProcessAction(ExistingProcessAction.FAIL)
                .startFailFast(true)
                .processTimeout(30_000L)
                .taskQueueTimeout(30_000L)
                .taskExecutionTimeout(120_000L)
                .maxTasksPerProcess(50)
                .build();
        try {
            candidate.start(); // 由管理器启动Office，并等待连接建立
            manager = candidate; // 只有启动成功才保存实例
        } catch (Exception exception) {
            OfficeUtils.stopQuietly(candidate); // 启动失败时清理本次管理器
            throw exception;
        }
    }

    @Override
    public synchronized void close() throws Exception {
        if (closed) return;
        closed = true; // 之后的convert不允许再启动Office
        OfficeUtils.stopQuietly(manager);
        manager = null;
        deleteTree(work);
    }

    private static void deleteTree(Path directory) throws Exception {
        try (Stream<Path> paths = Files.walk(directory)) {
            for (Path path : paths.sorted(Comparator.reverseOrder()).toList()) {
                Files.deleteIfExists(path); // 只清理本实例创建的临时目录
            }
        }
    }

    public static void main(String[] args) throws Exception {
        if (args.length != 3) {
            throw new IllegalArgumentException("参数：Office安装根目录 输入文件 输出PDF");
        }
        try (OfficeToPdf converter = new OfficeToPdf(args[0])) {
            converter.convert(Path.of(args[1]), Path.of(args[2]));
            System.out.println(Path.of(args[2]).toAbsolutePath());
        } // 命令行验证运行一次就退出，因此在这里关闭管理器
    }
}

main用于单文件验证，执行完会调用close。放进长期运行的服务后，在服务启动时创建一个OfficeToPdf实例，让后台队列反复调用它的convert，服务退出时再关闭。不要在每个HTTP请求里使用try (new OfficeToPdf(...))，否则每次请求都会重新启动Office。NEVER_EXECUTE 明确禁止执行文档宏，但不替代操作系统层面的隔离。宏执行策略

4.4 编译、运行和判断结果

在含 pom.xml 的示例根目录执行，以下类路径写法适用于 Linux：

mvn -DskipTests compile # 编译示例，先解决依赖、JDK或源码错误
mvn dependency:copy-dependencies -DoutputDirectory=target/dependency # 将运行所需依赖复制到示例target目录
java -cp 'target/classes:target/dependency/*' example.preview.OfficeToPdf /usr/lib/libreoffice /srv/preview-input/sample.doc /srv/preview-output/sample.pdf # 替换安装根目录、输入和输出，执行一次转换
pdfinfo /srv/preview-output/sample.pdf # 检查产物可解析，再用阅读器检查中文和分页

Windows 的类路径分隔符是 ;，例如 -cp "target/classes;target/dependency/*"，安装目录和文件路径含空格时分别加引号。

参数 示例含义 排障时先查什么
officeHome Office安装根目录 其下是否存在program/soffice或program/soffice.exe
workingDir Office工作目录 服务账号写权限、磁盘和inode空间
hostName、portNumbers 本机UNO连接 端口占用、重复启动、是否绑定到环回地址
startFailFast true 会等待启动和连接结果，失败就抛异常。false 会把启动交给后台任务 首次转换失败时查 Office 启动日志
processTimeout 示例给 Office 进程的启动、停止等管理操作设了 30_000 毫秒的等待限制 启动慢、缺库或残留进程
taskQueueTimeout 任务提交给 JODConverter 后，最多等 30_000 毫秒获取可用的 Office 进程 是否还有其他文档占用进程，以及应用自己的任务队列是否积压
taskExecutionTimeout 任务开始执行后，最多运行 120_000 毫秒，超时会中止该任务 文件复杂、密码保护或转换进程卡住
maxTasksPerProcess 示例每处理 50 个任务重启一次 Office 进程。设为 0 则取消按任务数重启 转换量大时，观察进程的内存占用和重启频率

例如，一个任务在应用队列里等了 20 秒，交给 JODConverter 后又等了 10 秒才拿到 Office 进程。taskQueueTimeout 只计算后面这 10 秒，taskExecutionTimeout 等开始转换才计时。前端轮询、文件下载和上传各自设置期限。JODConverter 4.4.10 超时配置

手工能转，放进服务就失败

先用实际运行服务的账号，在同一台机器或同一个容器内跑第 3 节的命令。手工测试时的账号、字体和文件权限可能与服务不同。soffice --version 成功只说明命令能启动，实际转出一页 PDF 才能顺带验证读写权限和转换组件。工作目录要能写，还要有空间容纳输入文件、临时文件和输出。

每个管理器使用自己的 UNO 端口。工作目录可以放在同一个可写父目录下，每次转换再创建独立子目录。同名文件并发处理时，分开的目录可以防止后一个任务读到前一个任务的 PDF。确认 manager.start() 成功后再提交转换。

上线验收时，用同一个服务实例连续转两份小文件，观察 soffice 进程及任务日志。正常情况下会复用进程，达到回收阈值或故障恢复时进程号可能变化。停止服务后，再检查它管理的 UNO 端口和进程是否释放。

5. 异步转换与前端轮询

文件一大，转换可能要等几秒到几十秒。申请接口先返回任务状态，前端定时查询，完成后再加载 PDF。下面是一组接口设计示例：

接口 职责
POST /api/document-previews 校验当前用户的文件读取权限，命中缓存则直接返回；否则提交有界异步任务
GET /api/document-previews/{previewId} 仅查询状态，不产生新任务；返回前再次鉴权
GET /api/document-previews/{previewId}/content 鉴权后返回PDF，或跳转到新签发的短期预览地址
GET /api/files/{fileId}/download 独立控制的原件下载接口，默认不开放

申请示例：

{"fileId":"sample-file-001"}

处理中返回示例：

{"previewId":"preview-001","status":"PROCESSING","pollIntervalMillis":2000}

成功示例：

{"previewId":"preview-001","status":"READY","previewUrl":"/api/document-previews/preview-001/content"}

状态使用 NOT_STARTED、PROCESSING、READY、FAILED、UNAVAILABLE。失败时，页面显示“文件有密码”“转换超时”等能说明问题的原因，完整异常写进服务日志。响应中不要带存储凭据和内部路径。

先用一个工作线程、小容量队列串行转换。队列满了就返回忙碌状态，提示稍后重试。部署多个实例后，还要通过共享任务锁避免同一份文件重复转换。

任务开始前先在请求线程确定授权范围和文件身份，传给后台的是已解析的存储位置及源版本；后台线程不能假定还保留着请求线程的登录上下文。

5.1 前端轮询示例

下面使用同源接口和 Cookie 登录态。需要额外认证头的系统，应交给现有 HTTP 客户端；不要把令牌放入URL。PDF如何呈现由已有阅读器处理。

async function requestJson(url, options = {}) {
  const response = await fetch(url, { credentials: 'same-origin', ...options });
  if (!response.ok) throw new Error(`预览请求失败：HTTP ${response.status}`);
  return response.json();
}

async function waitForPreview(fileId, signal) {
  const deadline = Date.now() + 180_000; // 每轮轮询检查的等待预算；单次HTTP请求还需配置超时
  let result = await requestJson('/api/document-previews', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ fileId }),
    signal,
  });
  while (true) {
    signal.throwIfAborted(); // 关闭弹窗或切换文件后，丢弃旧任务的页面结果
    if (Date.now() >= deadline) throw new Error('预览等待超时，请稍后重试');
    if (result.status === 'READY' && result.previewUrl) return result.previewUrl;
    if (result.status !== 'PROCESSING') throw new Error(result.message || '暂时无法预览');
    await new Promise(resolve => setTimeout(resolve, 2000)); // 仅查询状态，不反复提交转换
    signal.throwIfAborted();
    result = await requestJson(`/api/document-previews/${encodeURIComponent(result.previewId)}`, { signal });
  }
}

const controller = new AbortController(); // 每次打开文件都创建独立控制器
// const pdfUrl = await waitForPreview('sample-file-001', controller.signal);
// 将pdfUrl交给现有PDF阅读器，标题仍显示原文件名。
// 弹窗关闭、切换文件或组件卸载时调用controller.abort()。

前端取消轮询不等于服务端取消转换；后端可以完成已开始的转换并缓存结果。再次打开时查询已有结果，避免重复计算。失败时在弹窗展示错误与重试入口，不自动 window.open 原文件，否则“预览失败”可能变成意外下载。

两个容易漏掉的场景。第一，用户打开 A 后马上切到 B，A 的响应可能已经到达。更新弹窗前还要确认当前文件 ID 或请求序号，避免旧结果盖掉 B。第二，轮询间隔到了不代表单次 fetch 会结束。浏览器端要给请求设置超时，弹窗关闭时取消正在读的状态请求和 PDF 请求。

6. 缓存和文件更新

内容 适合放在哪里 什么时候失效
转换后的PDF 私有对象存储或受控文件目录 源版本变化、转换规则变化，或明确的清理策略
任务状态和锁 Redis或任务数据库 状态TTL、任务完成、租约结束或故障恢复
临时访问地址 每次通过鉴权后签发 签名到期；到期不代表PDF已删除

缓存身份至少包含授权域、源对象身份、源版本及转换规则版本。例如对这些字段的规范化组合计算 SHA-256，得到预览对象名。不要只以文件名作为缓存键；两个目录中的 sample.doc 不是同一份文件。

对象存储启用版本控制时，优先绑定确切的源版本。使用 ETag 时，不把它一概当成文件MD5；读取时增加版本条件，防止查询元数据后源文件已被替换。Office版本、字体或转换规则改变后，可以提高转换规则版本，避免继续复用旧版式。

处理顺序建议为：鉴权 → 确定源版本 → 查PDF产物 → 原子认领任务 → 提交队列。只有本次认领任务的持有者可以更新状态和释放锁，避免超时后的旧任务误删新任务锁。租约要覆盖排队、下载、转换、上传，或采用续期；不能只按转换的120秒估算。

例如状态保留30分钟，访问地址有效15分钟，PDF保留到对象生命周期清理，这三项可以互不相同。状态过期后先查产物；PDF仍在就签发新地址，不重新转换。只有“对象确实不存在”才当作缓存未命中，鉴权失败、网络故障和存储服务异常不能被吞掉后反复重转。

先验证 PDF 可读取，再把产物保存完成，最后写 READY。否则前端看到成功状态就去读文件，可能拿到 404 或不完整的 PDF。任务入队后若发现源对象版本变了，应按新版本重新申请，避免把新内容写进旧版本的缓存。某个任务的租约过期后，旧任务也不能再把当前状态改回 READY。

7. 文件读取、跨域和下载

文件链接可以在新标签页打开，不代表页面中的 JavaScript 能读取它。页面与文件地址的协议、主机或端口不同，就可能遇到 CORS；HTTPS页面读取HTTP文件还可能触发混合内容限制。

优先让浏览器通过同源文件接口读取：浏览器 → /api/.../content → 文件服务 → 私有对象存储。文件服务根据文件ID查找已授权对象，不直接请求用户提交的任意URL。必须兼容URL参数时，只解析服务端已配置存储中的对象，并再次检查对象权限，防止变成任意地址代理。

若直接给浏览器签名URL，需要存储服务允许准确的页面源，并确认浏览器能到达目标地址。CORS解决不了内网地址不可达、签名过期或文件不存在。跨域读取、原文件解析、Office转换和PDF展示是不同阶段，先根据 Network 找到失败阶段。

状态显示 READY 但阅读器打不开时，先在 Network 看实际 PDF 请求。401/403 先查登录态或签名，404 查产物和路由。即使是 200，也要看响应类型和响应体。若返回的是登录页、网关错误页或 JSON，PDF 阅读器同样会报解析失败。预览接口成功响应应返回 application/pdf。如果阅读器使用 Range 分段读取，还要检查代理是否正确转发 Range，并保留 206 和 Content-Range。

原件下载应与预览分别授权，默认不开启原件下载接口。隐藏前端按钮不能代替后端检查。PDF预览本身也会向浏览器传输内容，不能承诺彻底防保存、复制或截图；只展示页面图片同样无法消除这一限制。

8. 空文件怎么处理

正常保存的空白 DOC、XLS、PPT 仍有完整的文件结构，可以交给Office打开。真正的0字节文件只有一个空对象，即使后缀是.doc，也没有文档结构可转换。

遇到0字节文件，直接提示“文件无内容”，跳过转换。需要继续打开阅读器时，可以返回一页有效的空白 PDF，并标明源文件为空；原件保持不动。空白 PDF 本身仍要有正确结构，不能只创建一个0字节的.pdf。

只读文件接口是否允许返回空字节，与转换器是否接受空源文件应分别处理。不要让转换前校验阻断所有格式的原文件读取，也不要用空白预览掩盖权限不足、404或下载失败。

9. 转换失败时查哪里

现象 先检查 处理与复查
Office找不到 officeHome/program及运行账号 修正根目录；用同一账号执行版本检查

退出正常但没有PDF 完整日志、输出目录、同名旧产物 使用独立目录重新验证；检查真实产物，不能只看退出码

Linux常用检查命令：

ps -ww -eo pid,ppid,user,args | grep '[s]office' # 查看进程归属和参数，区分多个Office实例
sudo ss -lntp 'sport = :2002' # 检查示例UNO端口的监听地址与进程

安装目录错误与权限问题不能靠chmod -R 777、关闭SELinux或让整个服务提权来解决。用户配置目录独立可减少实例冲突，但不是文件系统或网络安全隔离；处理上传文件时，限制转换进程可访问的目录、网络、CPU和内存，并为下载、转换和上传分别设定上限。

10. 上线前跑哪些文件

  • 使用真正的 .doc、.xls、.ppt 各一份，检查中文、图片、表格和页数；另测正常空白文档与0字节文件。
  • 检查首次转换、命中缓存、源文件更新、签名到期和状态过期，确认不会复用其他文件的预览。
  • 测试并发提交、队列满、Office启动失败、超时和服务重启，确认有明确错误，任务不会无限PROCESSING。
  • 关闭弹窗、切换文件和快速重复打开，确认旧轮询不会覆盖新文件；预览失败不触发下载。
  • 使用无权限账号、已删除文件和外部URL验证边界，确认只读预览不会自动开放原件下载。
  • 验证结束清理测试临时目录；预览产物的保留期按存储生命周期管理，不与状态TTL混为一谈。
