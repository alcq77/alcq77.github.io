Linux 服务器常用运维命令

知知行笔记·约 33 分钟阅读
linuxservershellsshfilespermissionsnetworkoperations

Linux服务器日常检查、文件管理、权限处理、SSH传输和故障排查的常用命令。

命令采用Bash写法，示例中的目录 /opt/demo、用户 demo 和IP 192.0.2.10 按实际环境替换。安装软件、改权限、修改网络、停止服务和删除文件等操作按需单独执行。

命令不存在？展开查看常用工具安装方法

先确认系统，不要把不同发行版的命令整段一起执行：

cat /etc/os-release # ID和VERSION_ID用于确认系统
command -v sudo curl ss lsof iostat rg tmux # 查看已安装命令

示例：Ubuntu/Debian用apt，RHEL/Rocky/AlmaLinux等通常用dnf；旧系统可能只有yum。普通用户安装需要相应sudo授权，没有授权时请管理员操作。

命令 Ubuntu / Debian 包名 RHEL系常见包名
top、free、ps、pgrep、vmstat procps procps-ng
ip、ss iproute2 iproute
lsblk、findmnt、lscpu、namei util-linux util-linux
iostat、pidstat sysstat sysstat
lsof lsof lsof
nc netcat-openbsd nmap-ncat
dig、nslookup dnsutils bind-utils
rg ripgrep ripgrep，可能需获准的附加仓库
mtr mtr-tiny或mtr mtr
其他 curl、wget、rsync、unzip、tmux、tcpdump、traceroute、openssl 通常同名

Ubuntu / Debian按需选择软件包：

sudo apt-get update # 刷新软件包索引
sudo apt-get install sysstat lsof netcat-openbsd dnsutils ripgrep
sudo apt-get install curl wget rsync unzip tmux tcpdump traceroute mtr-tiny openssl

示例：只缺 iostat 时，刷新索引后只需 sudo apt-get install sysstat，不必安装整个列表。

RHEL / Rocky / AlmaLinux按需选择软件包：

sudo dnf install sysstat lsof nmap-ncat bind-utils
sudo dnf install curl wget rsync unzip tmux tcpdump traceroute mtr openssl
dnf info ripgrep # 确认已批准的软件源是否提供ripgrep

示例：rg不在现有仓库时可先用 grep -RnsE '关键词' /opt/demo。附加仓库由管理员按系统版本批准。

CentOS 7：先检查已有仓库，再安装缺少的工具，下面两条安装命令也按需选择：

cat /etc/centos-release # 确认是CentOS 7，其他发行版可能没有此文件
yum repolist           # 查看当前启用仓库及可用包；可能需要访问软件源
sudo yum install sysstat lsof nmap-ncat bind-utils # iostat/pidstat、文件占用、TCP与DNS检查
sudo yum install curl wget rsync unzip tmux tcpdump traceroute mtr openssl # 传输、终端及网络工具
yum provides '*/rg'     # 查询现有批准仓库是否提供rg，不自动添加EPEL

示例：只缺 ss 时安装 iproute；只缺 top/free/ps 时安装 procps-ng；只缺 findmnt/lsblk 时安装 util-linux。CentOS 7 的包名与上表RHEL列大多相同，具体以 yum provides '*/命令名' 查询结果为准。

CentOS 7已于2024年6月30日结束维护。这些步骤用于维护已有服务器，新部署选择仍受维护的系统。出现 Cannot find a valid baseurl 或镜像列表失效时，先核对DNS、网络及repo配置；原发行仓库已归档的情况由管理员提供批准的CentOS 7归档镜像或内部源。归档不提供持续安全更新，不改用Stream/Rocky的软件源、不关闭GPG/TLS校验，也不为了补工具执行整机升级。

安装后验证：

command -v iostat pidstat lsof nc dig rg tmux
iostat -V
nc -h # netcat不同实现的选项会有区别
rg --version

示例：安装sysstat使采样命令可用；是否开启长期历史采集是额外配置，不需要为了运行一次 iostat 就启动全部采集任务。安装不会在本文所述场景中自动配置目标业务服务。

普通用户登录后，权限不足怎么处理

先确认当前身份和授权

whoami    # 当前用户名
id        # 用户、主组和附加组
sudo -l   # 查询允许以sudo执行哪些命令，可能提示输入密码

示例：SSH以 demo 登录，whoami 返回 demo。如果 sudo -l 显示允许执行某些 systemctl 命令，就只按授权范围使用；不代表可以执行所有管理员命令。

情况 使用方法
有sudo授权 在需要权限的那一条命令前加 sudo
只允许部分命令 按 sudo -l 显示的命令和参数执行
没有sudo授权 请管理员执行，或授予具体命令/目录的必要权限
已获准使用root身份且有对应凭据 可按管理制度使用 su - 或已授权的 sudo -i
文件位于个人目录 通常直接操作，不需要sudo

普通用户不能凭一条命令自行获得尚未授予的管理员权限。也不要为省事默认开放root远程登录或全量免密sudo。

sudo 的常见用法

sudo systemctl status demo-api --no-pager -l # 用管理员权限查看服务
sudo systemctl restart demo-api             # 用管理员权限重启，会中断服务
sudo journalctl -u demo-api -n 100 --no-pager # 读取服务日志
sudo ls -lah /root                          # 有授权时查看受限目录
sudo -u demo id                             # 以指定用户执行，须被授权
sudo -k                                    # 清除当前sudo认证缓存

示例：普通用户 systemctl status 通常可用，但完整日志、其他用户的进程信息和启停操作可能需要提权。sudo通常要求输入当前登录用户的密码，不是root密码；具体取决于服务器策略。终端输入密码不显示字符是正常行为。

sudo -i  # 获准时进入root登录环境
whoami   # 核对是否为root
exit     # 完成后退出root shell，返回原用户

示例：只执行一条管理命令时优先单条sudo。sudo -i 会改变身份、HOME和环境，完成后及时退出；再次 whoami 应回到原登录用户。su - 默认切换root，通常需要目标用户密码，目标账号锁定时可能不能使用。

编辑配置与 shell 重定向

sudoedit /etc/systemd/system/demo-api.service # 用获准的编辑方式修改配置
sudo systemctl daemon-reload                 # 单元文件修改后重新加载

示例：sudoedit 在策略允许时用当前用户的编辑器编辑临时副本，再以特权写回；可用范围取决于sudo授权。不要把配置文件永久改成普通用户所有来绕过编辑权限。

下面这种写法可能仍然报 Permission denied：

sudo echo 'example' > /etc/demo.conf

示例：echo被提权，但 > 是当前普通用户的shell先执行的，写文件仍被拒绝。上面仅说明错误写法，不要尝试覆盖已有配置。

这里的 > 把标准输出写入文件，会覆盖原内容；>> 是在末尾追加。两者在目标文件不存在且目录权限允许时都会创建文件。

如果确实要创建一个新的演示文件，可将输出交给有权限的 tee：

printf '%s\n' 'example' | sudo tee /etc/demo-example.conf > /dev/null

示例：权限作用在真正写文件的 tee 上。tee 默认覆盖文件，tee -a 才是追加；修改正式配置优先使用编辑器或受控发布，不能重复追加同一段配置。

这条命令中，| 将 printf 的标准输出送给 tee；tee 写文件的同时也会把内容输出到终端，因此末尾 > /dev/null 只丢弃这份标准输出，不影响前面的文件写入。/dev/null 可以理解为丢弃写入内容的特殊设备。

sudo sh -c 'cd /root && pwd' # 确有需要且获准时，在提权shell中执行内建命令

示例：cd 是shell内建命令，sudo cd /root不能改变当前shell目录。通常无需进入受限目录，直接 sudo ls /root 更清楚；不要把不可信变量拼入 sh -c。

上传文件先暂存，再由管理员安装

scp ./app.jar demo@192.0.2.10:~/app.jar.new # 从本机上传到用户自己的目录

示例：普通用户无法直接上传到root所有的发布目录时，先上传自己的HOME目录；SCP不能通过在远端路径前写sudo来提权。

登录目标服务器后，在已安排的发版流程中执行：

sha256sum "$HOME/app.jar.new" # 核对上传后的包
sudo systemctl stop demo-api # 停服并确认原进程退出后再替换
sudo install -o demo -g demo -m 0644 "$HOME/app.jar.new" /opt/demo/app.jar
sudo systemctl start demo-api

示例：这里假设服务账号/组为 demo，且原包已备份。install会覆盖目标文件并设置属主和权限；实际账号、文件名与配置以服务为准，不直接复制到运行中的JAR上。

服务目录与日志读取

ls -ld /opt/demo /opt/demo/logs # 先检查属主和权限
sudo tail -n 100 /opt/demo/logs/app.log # 临时读取受限日志
sudo ss -lntp 'sport = :8080' # 完整查看端口对应进程

示例：读取日志可以单条sudo，或由管理员通过专门的只读组/ACL授权。不应为了让维护账号看日志，把应用配置和数据目录全部开放写权限。journal读取权限通常可通过发行版对应日志组管理，但组名和授权范围需管理员核对。

PATH、环境变量和家目录变化

command -v java                    # 当前普通用户解析到的Java
sudo /opt/jdk17/bin/java -version  # 提权时使用已核对的绝对路径

示例：sudo可能使用受控PATH、过滤环境变量，因此用户能执行 java，sudo却提示找不到，或执行了另一套版本。明确绝对路径，不为方便默认使用 sudo -E 保留全部环境。

不要用sudo在用户项目里反复构建、解压或安装依赖，否则可能产生root所有的文件，后续普通用户无法修改。遇到这类问题先确认具体文件，再由管理员修复范围内的属主，不递归修改系统目录。

常见报错对照

报错或现象 处理
is not in the sudoers file 当前用户未被授予sudo，联系管理员
not allowed to execute 命令或参数不在授权范围，按最小范围申请
Authentication failure 核对当前用户密码、账号和sudo认证策略
sudo命令成功但 > 报错 重定向仍由普通shell执行，用受控编辑或sudo tee
sudo: command not found 可能没有安装sudo；需管理员通过已授权途径处理
sudo java: command not found 核对sudo PATH，使用正确绝对路径
Docker socket permission denied 使用获准的sudo或rootless方案；docker组权限很高，不默认加入
kubectl Forbidden 查集群身份与RBAC，本机sudo不自动获得集群权限
改了Unix权限仍不能访问 核对父目录、ACL、SELinux、只读挂载和远程存储策略

管理员若需配置sudo，应使用 visudo 或 visudo -f /etc/sudoers.d/指定文件 做语法校验，并保留可用管理会话；授权应限定必要命令与参数，不把“全部命令免密”作为默认配置。

1. 系统版本、时间、开机与负载

cat /etc/os-release # 发行版和版本
uname -r            # 内核版本
uname -m            # CPU架构
hostname            # 主机名
date                # 日期、时间、时区
timedatectl         # 时间同步与时区状态
uptime              # 连续运行时间和1/5/15分钟负载
uptime -s           # 最近开机时间
who -b              # 系统启动记录，依赖系统记录
nproc               # 当前可用处理器数量
lscpu               # CPU详情

示例：8核机器负载为 0.5 0.8 1.0，不代表CPU占用50%、80%、100%；负载还包含等待I/O等情况。时间不一致时先核对时区与同步，避免直接改时钟影响证书、任务调度和日志关联。

2. CPU、内存与实时观察

top                         # 实时查看进程
free -h                     # 内存和swap，重点看available
vmstat 1 5                  # 1秒采样，共5次
ps -eo pid,ppid,user,%cpu,%mem,stat,etime,args --sort=-%cpu | head -n 15
ps -eo pid,ppid,user,%cpu,%mem,stat,etime,args --sort=-%mem | head -n 15

示例：top 中按 P 排CPU、M 排内存、1 展开CPU，q 或通常 Ctrl+C 退出，只结束查看。free 中可回收缓存不是简单的“内存浪费”，不要为释放缓存随意清缓存。

ps ... | head -n 15 中的 | 是管道，把左边命令的标准输出交给右边；这里表示只显示排序结果的前15行（包括表头），不修改原进程。

iostat -xz 1 5   # 磁盘I/O，通常来自sysstat包
pidstat -p 24680 1 5 # 指定进程采样，通常来自sysstat包

示例：高负载但CPU不高时结合 vmstat 的等待进程、wa 与磁盘延迟分析。vmstat/iostat 首次输出常包含自开机以来的平均值，后续才是间隔采样。工具不存在时按发行版安装，不把“命令不存在”等同资源正常。

3. 当前目录与文件列表

pwd                    # 当前绝对路径
ls -lah                # 包含隐藏项、权限、大小
ls -lt                 # 按修改时间排序
stat /opt/demo/app.log # 文件元数据
file /opt/demo/app.jar # 文件类型判断
readlink -f /opt/demo/current # 解析符号链接实际目标

示例：日志路径看起来相同但内容不对时，用 readlink -f 核对是否指向旧版本目录。ls -l显示的是文件逻辑大小，磁盘实际占用可用 du 查看。

如果 ls -l 显示 current -> /opt/demo/releases/v1，其中 -> 表示左边的符号链接指向右边路径，是输出中的说明，不是Shell重定向命令；真正的输出重定向符是单独的 >。

4. 创建、复制、移动与安全删除

mkdir -p /opt/demo/backup           # 创建目录，缺失父目录一起创建
cp -a /opt/demo/conf /opt/demo/backup/conf-20261102 # 保留属性复制
cp -i /opt/demo/app.jar /opt/demo/backup/app.jar   # 覆盖前询问
mv -i /opt/demo/app.jar.new /opt/demo/app.jar      # 移动/重命名，覆盖前询问

示例：备份目录使用独立时间或版本名，防止覆盖上一份可用备份。cp -a 的目录目标已存在时可能形成嵌套目录，应先核对目标布局。

删除前先看清对象：

ls -ld -- /opt/demo/tmp/report.old # 核对路径
rm -i -- /opt/demo/tmp/report.old  # 询问后删除单个文件
rmdir /opt/demo/tmp/empty-dir      # 仅删除空目录

示例：-- 结束选项解析，避免以减号开头的文件名被当作参数。删除目录树会连同内容一起移除，不能恢复为常规“回收站”；不把 rm -rf、通配符删除放进日常巡检流程。

5. 文件查找与内容搜索

find /opt/demo -type f -name '*.log'           # 按文件名查找
find /opt/demo/logs -type f -mtime +7 -print  # 预览超过7天的文件
find /opt/demo -type f -size +100M -print     # 大文件
rg -n 'ERROR|Exception' /opt/demo/logs        # 带行号搜索，需ripgrep
grep -nE 'ERROR|Exception' /opt/demo/logs/app.log # 无rg时使用grep
grep -Rns --include='*.yaml' 'server:' /opt/demo/conf # 递归查配置

示例：先用 find ... -print 确认对象，不直接改为 -delete。-mtime +7 按24小时取整计算，不是“日历上7天之前”的精确分界。搜索配置可能看到密码，分享结果前脱敏。

sed -n '100,150p' /opt/demo/logs/app.log # 只打印100到150行
head -n 30 /opt/demo/logs/app.log       # 前30行
tail -n 100 /opt/demo/logs/app.log      # 最近100行
tail -F /opt/demo/logs/app.log          # 跟踪文件名，适合轮转后的日志
less /opt/demo/logs/app.log             # 分页查看

示例：less 中 /ERROR 搜索、n 下一个、Shift+N 上一个、q 退出。tail -F 按 Ctrl+C 只退出日志跟踪；不要推广到所有前台命令，前台服务可能会因此停止。

6. 压缩、解压与校验

tar -czf /opt/demo/backup/conf.tgz -C /opt/demo conf # 相对路径归档
tar -tzf /opt/demo/backup/conf.tgz                  # 先列出归档内容
mkdir -p /opt/demo/restore-test                     # 准备空目录
tar -xzf /opt/demo/backup/conf.tgz -C /opt/demo/restore-test # 解压
unzip -l /opt/demo/release.zip                      # 查看zip内容
unzip /opt/demo/release.zip -d /opt/demo/release-test # 解压到单独目录
sha256sum /opt/demo/app.jar                         # 哈希校验

示例：归档里的 conf/... 解压到 restore-test/conf/...。先查看再解压，不对生产目录直接解压未知压缩包；源端与目标端SHA-256一致可确认传输内容一致，不代表来源可信。

7. 用户、组与权限

whoami                         # 当前用户
id                             # 当前UID、GID与组
id demo                        # 指定用户身份
getent passwd demo             # 查询系统用户信息
ls -ld /opt/demo /opt/demo/logs # 目录权限与属主
namei -l /opt/demo/logs/app.log # 逐级查看路径权限，需工具可用
sudo -l                        # 当前身份的sudo授权
umask                          # 新文件默认权限掩码

示例：进程能读取文件却无法写日志，检查文件本身及所有父目录的访问权限、属主、只读挂载和SELinux，不直接递归开放全部权限。

sudo chown demo:demo /opt/demo/logs    # 调整指定目录属主，不递归
sudo chmod 750 /opt/demo/logs         # 目录：属主全权限、组读和进入
sudo chmod 640 /opt/demo/conf/app.yml # 文件：属主读写、组只读
chmod u+x /opt/demo/bin/start.sh      # 给属主增加执行权限

示例：目录的 x 表示可以进入/遍历，不等同普通文件的执行。改权限前确认服务实际运行用户；不用 chmod -R 777 作为通用修复。

8. 进程、文件句柄与优雅停止

pgrep -af 'demo-api.jar'                       # 完整命令行匹配
ps -ww -p 24680 -o pid,ppid,user,stat,etime,args # 指定进程
sudo readlink -f /proc/24680/exe               # 可执行文件
sudo readlink -f /proc/24680/cwd               # 工作目录
cat /proc/24680/limits                         # 进程实际限制
ulimit -n                                     # 当前shell文件描述符限制
sudo lsof -p 24680                            # 打开的文件，需lsof

示例：ulimit -n 不是所有服务的实际限制，systemd服务应查其配置和对应 /proc/PID/limits。查询完整命令可能显示启动参数中的凭证，分享前脱敏。

优先通过原管理器停止；仅对确认由手动启动的进程按需发信号：

kill -TERM 24680              # 请求优雅退出
ps -p 24680 -o pid,stat,args # 等待后确认是否退出，核对PID身份

示例：SIGTERM允许应用清理连接和落盘。kill -KILL 不执行应用清理，只在无法正常退出且确认影响后使用；托管进程被直接杀死还可能由管理器拉起。

9. 磁盘、inode、挂载与删除未释放

df -hT                       # 文件系统容量和类型
df -i                        # inode使用量
lsblk -f                     # 块设备与文件系统
findmnt                      # 挂载关系
findmnt -T /opt/demo          # 指定路径所在挂载
du -xhd1 /var/log 2>/dev/null # 单文件系统内一级目录占用
sudo lsof +L1                # 已删除但仍被进程打开的文件

示例：df显示满、du不大时，检查删除但仍打开的日志、被挂载遮盖的内容、权限范围和预留空间。inode耗尽时，小文件也无法新建。释放已删除文件需由相应进程关闭句柄，按业务方式重开日志或维护重启，不随意操作 /proc/PID/fd。

2>/dev/null 中的 2 表示标准错误，把权限不足等报错丢弃，正常结果仍显示；它只是隐藏报错，不会修复权限，也不表示目录统计完整。排障时需要看错误就去掉这一段。

分区、格式化、扩容、卸载文件系统有数据与可用性影响，先确认设备、挂载、备份和具体文件系统方案，不使用一套命令盲目套用。

10. 网卡、地址、路由、DNS

ip -br addr                           # 网卡与IP
ip link                               # 链路状态
ip route                              # IPv4路由
ip -6 route                           # IPv6路由
ip route get 192.0.2.10                # 实际出口、源地址和路由
cat /etc/resolv.conf                   # 解析器配置，可能由系统生成
getent hosts example.com              # 按系统名称服务解析
dig example.com                       # DNS查询，需dns工具

示例：getent会遵循系统名称服务配置，可能命中hosts；dig主要查DNS，两者结果不一致时核对hosts、搜索域和解析器。不要直接覆盖由NetworkManager或systemd-resolved生成的文件。

11. 监听端口与连通性

sudo ss -lntp                       # TCP监听与进程
sudo ss -lnup                       # UDP监听与进程
sudo ss -lntp 'sport = :8080'        # 指定监听端口
ss -s                              # socket汇总
ping -c 4 192.0.2.10               # ICMP可达性，可能被禁用
nc -vz -w 3 192.0.2.10 8080        # TCP连接测试，参数随nc实现而异
curl -i --connect-timeout 3 --max-time 5 http://192.0.2.10:8080/health

示例：TCP连通只代表建立连接，HTTP401需看认证、404需看路径；/health 必须是实际存在的只读接口。127.0.0.1监听仅供本机访问，0.0.0.0是IPv4通配监听；IPv6通配是否也接收IPv4以系统和程序配置为准。

traceroute 192.0.2.10 # 路由跳数诊断，需安装
mtr -rw -c 10 192.0.2.10 # 路径采样，可能需要权限
openssl s_client -connect example.com:443 -servername example.com -verify_hostname example.com -verify_return_error < /dev/null

示例：中间跳不回应不一定代表业务丢包；TLS检查带正确SNI与主机名校验，并结合本机信任库检查证书链。不要用跳过证书校验作为长期修复。

CentOS 7上的旧OpenSSL先用 openssl version、openssl s_client -help 核对选项；若不支持 -verify_hostname，HTTPS可用 curl -I --connect-timeout 3 --max-time 5 https://example.com/ 检查证书链与域名。私有CA通过 --cacert /path/to/ca.pem 指定；不能仅删除主机名校验后把握手成功当作验证通过。TLS 1.3还要求程序和链接的TLS库支持。

< /dev/null 将标准输入接到空设备，程序读到的输入会立即结束，而不是继续等待键盘输入。< 管输入，> 管输出，方向不同。

抓包需要授权与数据范围控制，文件可能包含业务或认证信息：

sudo tcpdump -i any -nn -c 50 'host 192.0.2.10 and tcp port 8080'

示例：最多捕获50个匹配包，观察握手/重传等；-c 限制包数不限制等待时长，可用 Ctrl+C 提前结束。不要无过滤长时间抓取整个网卡流量。

12. SSH、SCP 与 rsync

ssh -p 22 demo@192.0.2.10                 # 登录
ssh -i ~/.ssh/id_ed25519 demo@192.0.2.10 # 使用指定密钥
ssh -v demo@192.0.2.10                    # 排查连接与认证
scp -P 22 ./app.jar demo@192.0.2.10:/opt/demo/releases/ # 上传
scp -P 22 demo@192.0.2.10:/opt/demo/logs/app.log ./app.log # 下载

示例：SSH端口参数是小写 -p，SCP端口是大写 -P。首次连接核对服务器指纹，不默认关闭host key校验；ssh -v输出也可能暴露用户名与路径，分享前检查。

rsync -av --dry-run ./release/ demo@192.0.2.10:/opt/demo/releases/ # 预览
rsync -av ./release/ demo@192.0.2.10:/opt/demo/releases/           # 同步

示例：源目录尾部 / 表示复制其内容；没有尾部斜杠时目录层级可能不同。rsync需要相关端安装；不默认使用 --delete，它会删除目标端多出的文件。应用包先传暂存目录，不能直接边传边覆盖运行包。

13. systemd 服务和日志

systemctl status demo-api --no-pager -l # 服务状态
systemctl is-active demo-api           # 是否活动
systemctl is-enabled demo-api          # 是否自启
systemctl cat demo-api --no-pager       # 文件及覆盖配置
systemctl --failed --no-pager           # 失败单元
sudo journalctl -u demo-api -b -n 100 --no-pager # 本次开机最近日志
sudo journalctl -u demo-api --since '2026-11-02 10:00:00' --until '2026-11-02 10:10:00' --no-pager
sudo journalctl -u demo-api -f          # 实时日志

示例：按事故时间缩小日志范围，确保服务器时间与排查时间使用相同时区。active不替代业务检查；enabled不表示当前进程在运行。

以下会更改状态，按需单独执行：

sudo systemctl start demo-api       # 启动
sudo systemctl stop demo-api        # 停止
sudo systemctl restart demo-api     # 重启，会中断业务
sudo systemctl reload demo-api      # 仅服务实现了reload时可用
sudo systemctl enable demo-api      # 开机自启，不立即启动
sudo systemctl disable demo-api     # 关闭自启，不立即停止
sudo systemctl daemon-reload        # 修改单元配置后重新读取

示例：修改Nginx配置后先做 nginx -t，再按服务原管理方式reload；不是所有服务都支持reload。详细配置见 systemd自启与管理。

14. 内核、OOM、登录与操作线索

sudo journalctl -k -b -n 100 --no-pager          # 本次开机内核日志
sudo journalctl -k -b --no-pager | grep -Ei 'oom|out of memory|killed process|I/O error'
last -x | head -n 30                            # 登录、关机、开机记录
who                                            # 当前登录用户
w                                              # 用户与当前活动
history | tail -n 50                            # 当前shell历史

示例：发现服务在SSH退出时停止，不能只凭时间相同断定有人关闭；需结合应用退出日志、内核OOM、信号、会话和审计记录。history可不完整、无时间或尚未写盘，不能作为完整责任认定依据。

journalctl ... | grep ... 是把日志的标准输出交给 grep 筛选，last -x | head -n 30 则只展示前30行；普通 | 不会自动把左边命令的标准错误一起传过去。

发行版常见认证日志：RHEL系可能为 /var/log/secure，Debian系可能为 /var/log/auth.log，也可能集中在journal。未提前启用审计时，通常无法事后完整还原每一次kill是谁发出的。

15. cron 与系统定时器

crontab -l                      # 当前用户计划
sudo crontab -u demo -l          # 指定用户计划
ls -l /etc/cron.d /etc/cron.daily # 系统计划目录
systemctl list-timers --all      # systemd timers
systemctl cat demo-backup.timer demo-backup.service --no-pager # 查看任务配置

示例：查重复自启时同时检查用户cron、系统cron、systemd和应用自身调度。crontab -e会修改计划，crontab -r会删除整份计划，不当作查看命令。

# 每天02:30，以该crontab所属用户执行；目录需可写
30 2 * * * /bin/bash /opt/demo/bin/backup.sh >> /opt/demo/logs/backup.log 2>&1

示例：cron环境比交互shell精简，脚本里使用绝对路径，明确PATH、工作目录、时区和锁；任务可能重叠，不能假设上一次一定已结束。标准crontab五个时间字段依次为分、时、日、月、星期。

末尾 >> /opt/demo/logs/backup.log 2>&1 先把标准输出追加到日志，再让标准错误也写到同一位置，所以正常信息和报错都会保留。1 代表标准输出，2 代表标准错误；2>&1 中的 &1 是文件描述符1，不是名为“1”的文件，也不是后台运行符。重定向按从左到右处理，不能随意调换顺序。

16. 软件包与命令位置

command -v java          # 当前PATH中的命令
type -a java             # 所有解析结果，包含别名等
java -version            # 当前实际Java版本
rpm -q curl              # RHEL系查询包
dnf info curl            # 新版RHEL系包信息
dpkg-query -W curl       # Debian系查询包
apt-cache policy curl    # Debian系候选/已安装版本

示例：按发行版选择rpm/dnf/yum或dpkg/apt，不能混用；自定义安装的Java、Nginx、Redis未必在系统包管理器里。

缺少工具时，展开本文开头的“常用工具安装方法”，按发行版安装；不为一次排障直接执行整机软件升级。

17. 防火墙与 SELinux

systemctl is-active firewalld        # firewalld状态
sudo firewall-cmd --get-active-zones # 活动zone
sudo firewall-cmd --zone=public --list-all # 仅当实际zone为public
sudo ufw status verbose             # 使用ufw的系统
sudo nft list ruleset               # 使用nftables的系统
getenforce                          # SELinux模式，需系统启用相关工具
ls -Zd /opt/demo /opt/demo/logs      # SELinux上下文

示例：这些是不同防火墙管理方式，不要求都安装；按机器实际使用的工具查询。云安全组、负载均衡和Docker转发规则还要分别检查。排障不以关闭整个防火墙、停用SELinux作为默认方案。

来源受限的firewalld运行时放行示例：

sudo firewall-cmd --zone=public \
  --add-rich-rule='rule family="ipv4" source address="192.0.2.20/32" port port="8080" protocol="tcp" accept'

示例：只在确认活动zone为public、授权来源为该IP时使用。运行时规则重载后可能丢失，验证有效后按同一规则增加 --permanent 持久化；更详细步骤见 服务检查与排障。

18. 会话保持与后台作业

tmux new -s ops            # 创建会话，需安装tmux
tmux ls                    # 会话列表
tmux attach -t ops         # 重新连接
jobs -l                    # 当前shell后台作业

示例：tmux中按 Ctrl+B 后按 D 让会话继续运行并脱离；exit会结束当前shell，最后窗口结束后会话也结束。tmux用于交互维护，不代替长期服务的systemd管理。

nohup、&、disown、setsid解决的范围不同，不能自动保证开机恢复、应用健康或故障重启。部署服务优先采用已有管理机制。

19. 备份、发版与重启前检查

date                              # 记录当前时间
df -h                             # 检查空间
systemctl --failed --no-pager       # 已有失败服务
systemctl is-enabled demo-api      # 核对自启
sha256sum /opt/demo/releases/app.jar # 新包校验

示例：发版前备份原包、配置及必要数据，确认回滚兼容性；重启服务器前检查关键依赖、自启和远程恢复路径。重启后核对日志、端口、协议和关键业务，不能只看服务器能SSH登录。

sudo systemctl reboot # 计划内重启整台服务器，会中断连接和服务

示例：仅在已安排维护、确认影响后执行，不作为修复所有问题的第一步；数据库和有状态服务尤其要有一致性与恢复方案。

20. 常见问题速查

现象 先看什么
服务器很慢 uptime/top → vmstat → 内存 → I/O → 具体进程
磁盘满 df容量与inode → du → 删除未释放 → 日志/容器存储
端口不通 监听及归属 → 本机协议 → 路由 → 防火墙/安全组
服务突然退出 应用日志 → journal → 内核OOM → 管理器事件与审计
SSH断开后服务没了 原启动方式、终端信号、会话策略、进程管理
文件存在却Permission denied 用户/组 → 父目录权限 → 挂载 → SELinux
重启后配置不一致 实际单元 → WorkingDirectory → 环境与配置路径
日志时间对不上 系统时区、应用时区、日志格式、时间同步
改文件没生效 是否改到符号链接旧目标、容器挂载或另一套配置

更短的状态速查见 Linux系统状态查看。容器命令见 Docker与Compose、Kubernetes。各命令以本机 man 与 --help 为准。
